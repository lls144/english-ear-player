# V1.4 lyric interaction

Existing source materials, neutral pronunciation plans, model settings, 360 MP3 bytes and timing maps remain unchanged. This is a UI-only release with playback interaction fixes; no remote note read or synthesis is needed.

A lyric tap always starts playback. All/one/off modes pause the old request, find the stable sentence ID in the selected preset's verified chapter cue map, seek the persistent audio element, and play without reloading a healthy chapter. A latest-only pending seek handles metadata/canplay; it also supplies immediate focus while buffering. Single-sentence mode switches the corresponding independent file and native loop. TTS cancels previous work and starts that sentence's actual speech text offset. Imported files have no guessed timeline: their association is retained, while an exact text jump uses the built-in chapter.

Following has five states: FOLLOWING, USER_INTERACTING, MOMENTUM_SCROLLING, AWAITING_NEXT_LINE, ANIMATING_TO_LINE. Touch/pointer/wheel/keyboard input cancels program motion; native scroll events extend the momentum quiet period. A new audio cue during a gesture is deferred until momentum settles. A settled browse waits for a genuine next cue, not an idle timer. A fresh touch supersedes an old pending return. Layout/program scrolls are tracked separately. Repeated native wraps of one stable sentence never retrigger focus travel.

The list uses an underdamped oscillator (omega 21, damping ratio .84), carrying bounded same-direction velocity between focus changes. Rebound is capped at 8px, with a precise final position. Visible rows share small 14ms stagger steps (84ms maximum) and bounded 24px lag, with at most 6px extra separation per row. The upper rows begin first and the lower rows catch up. Current text scales to 1.03 inside its stable box; future text uses .99 and past text .985. Scaling changes no line wrapping. Long sentences scale from the top-left, anchor just below navigation and remain naturally scrollable. Gaussian blur affects only rows near the viewport, with separate past/next/far amounts; current audio stays sharp. Browsing removes the filters without changing the real current cue. Reduced motion/contrast and sustained slow-rendering fallback stay clear.

The 110px dock contains 13px elapsed/remaining times (12px in compact layouts), a 6px progress rail, larger rounded transport glyphs and one of four distinguishable loop SVGs. Transport glyphs have no permanent circular backing; their hit targets remain at least 44px. The rail sits below generous top padding. The fill uses a composited scale transform, while clock text changes only when its displayed value changes, avoiding per-frame text/layout churn. Presets/rates and direct loop choice live in More settings. Loop long-press opens that selection. No chapter caption, selected dot, loop text or return-current button occupies the dock/page. Native range input retains its 44px interaction area. During drag, a separate painted rail eases from translucent 6px to white 12px; timestamps preview the chosen point. Audio continues, release commits once, cancellation restores the real clock. TTS exposes percent, never invented audio timestamps.

Private evidence includes a real screen recording, intermediate spring/rail frames, actual audio clocks and native Chromium touch momentum. The recorded native touch continued about 110px after lift; this is browser emulation, not physical iPhone inertia. Rail capture records zero seeks during preview and one seek on release, with dozens of measured intermediate thickness values. Software Windows WebKit is profiled separately: full filters are expensive on this host, while quiet rendering returns to about 16ms frame intervals. The automatic fallback is actually triggered and measured; these numbers do not establish physical iPhone performance.

All native media, source, unit, production-browser, PWA, privacy-history and formal HTTPS gates remain mandatory. Focus/rail, gesture-window and nine-rate media-clock measurements run serial to avoid software-renderer contention, with every functional case, assertion and timeout retained. The initial four-worker Linux WebKit run passed 210 functional cases but missed three short gesture windows and exhausted the three 35s multi-rate budgets; both timing-sensitive groups now join the serial phase (204 functional plus 24 measured cases). Physical iPhone lock screen, calls, suspension, hardware frame rate and touch feel remain unverified.

Gesture injection is also kept on the browser clock: a captured 197ms automation round trip exceeded the real 180ms quiet interval even without concurrent browsers. The synthetic momentum regression now injects its three native scroll steps within one browser evaluation, records actual spacing below 180ms, and retains all three MOMENTUM_SCROLLING assertions plus the final real-cue recovery check. Native Android touch coverage remains separate.

The second shared-runner attempt exposed a lost synthetic release velocity and an iPad native media-clock stall. CI now gives each browser profile an independent standard Ubuntu runner and a single worker, with deployment depending on every matrix result. The Android gesture sends timestamped native touch events without waiting on each CDP acknowledgement, records the actual touchend timestamp in-page, and requires real movement after release. This preserves native inertia verification without tying its velocity to Node/CDP round trips. Reports have one-day retention; the six profiles remain mandatory.

Native startup acceptance also found a real liveness gap: monitoring began only after play() settled, and recovery assumed NETWORK_IDLE. A recorded Linux WebKit failure had currentTime 0.001246s, readyState 3, NETWORK_LOADING and a complete [0,193.2] buffer for a 193.2s file. Monitoring is now armed before play(), accepts a complete contiguous native time range even while loading is reported, and remains armed through the existing 60s loading grace. It retains a single bounded same-element reload, partial-stream protection, explicit-pause cancellation and observed-clock proof. Five new fault regressions cover pending promises, pause, loading/full/partial buffers and data arriving after six seconds; the unit total is 119.
