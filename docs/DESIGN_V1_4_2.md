# V1.4.2 continuous reading

The earlier frame fallback disabled ambient animations and lyric filters, while the playing class removed depth on pause. Chapter changes also combined a blanking text fade, two alternating background scenes and opaque/transparent dock changes. V1.4.2 separates these responsibilities.

One persistent blue/plum field runs two independent gradient paths lasting 22 and 27 seconds, including while paused. Each gradient is painted once into a 256px canvas texture; CSS composites its movement without repainting viewport-sized gradients every frame. Negative phase offsets start with visible motion. It stops when the document is hidden or reduced motion is requested. Chapter mounts preserve that same field and replace a complete document fragment in one task, without fading the transcript to zero. The header keeps a distinct translucent frosted surface, a faint upper sheen and a long softened lower edge without a solid plateau. The dock retains a consistently light 6px frosted backdrop and translucent fill; the header uses 4px blur, avoiding repeated wide high-radius rasterization and changes of material during travel. On wide tablet/desktop viewports its existing width is centered on the whole screen, bringing it left from the former reader-biased offset.

Sentence depth uses a symmetric bounded Gaussian of distance from the real current sentence. Pause keeps focus. A stationary pointer does not clear surrounding depth; a real drag, wheel or reading scroll does. Existing gesture/momentum states still defer recovery to an actual new cue. Only viewport-adjacent rows are filtered and prepared for compositing. During travel their blur remains static rather than repeatedly interpolating the filter. Frame budgets reduce row lag and shadows while retaining cached row layers, the requested depth and the continuous field. A delayed spring step remains bounded to 32ms normally, or 50ms under a slow-render budget, preventing focus travel from stretching over many seconds. Contrast and reduced-motion accessibility preferences remain readable.

The native range remains the keyboard/accessibility control. Pointer coordinates, rather than a browser's thumb-only behavior, control its full 44px hit area. Pointer capture follows movement beyond its edges. Down/move only preview; up commits once; cancel, capture loss and window blur restore actual time. Native input/change events remain available for keyboard and assistive interaction. The audio element, sources, Media Session and MP3 bytes are unchanged.

Press feedback suppresses the underlying CSS transform transition while the Web Animation owns the text. Its rise holds the compositor's terminal peak across two animation frames before a short settling animation returns to the current-sentence scale. A wall-clock timeout cannot erase the whole rebound before its first paint. Cancellation, chapter changes and hidden-page cleanup invalidate queued work. Sampling begins at the actual pointer release, retains every frame until settlement and checks the held scale, visible peak and entire post-peak tail. A second case blocks the real click's main thread for 900ms; an old-code control reproduces the lost peak without mocking media or animation state.

Startup observation also covers a fully buffered native seek that never finishes. After three seconds without progress, intended playback gets one pause/play restart on the same element and source, without reloading or seeking again. Partial streams retain their loading grace; user/system pauses and stale requests cannot restart. A second stall stops with an honest retry notice. Controller tests cover full/partial buffers, cancellation and the bounded retry; repeated browser cases still require actual advancing clocks and unchanged normal chapter loads.

Shared production/HTTPS browser cases measure computed depth while paused, actual animation progression, nonblank intermediate chapter frames, stable backdrop blur, native mobile touch taps away from the thumb, and captured/cancelled drags. Focus sampling starts before seeking, covers at least 1.1s after the actual audio cue and the entire bounded spring, and fails if it does not settle within an eight-second maximum. It retains all pre-cue frames, native seek latency and audio positions instead of mistaking an arbitrary partial snapshot for a finished spring. Step-count, destination and jump bounds are unchanged; sparse software frames are explicitly annotated rather than presented as physical frame-rate acceptance. Actual captures additionally compare background pixels over time. These are desktop browser automation results; physical iPhone/iPad/Android touch feel, rendering, lock screen and system interruptions remain unverified. Prior direct Windows WebKit network/EOF intermittence is retained as an environment limitation; explicit configured proxy use is recorded rather than calling a changed transport a code fix.
